# 0010 — PostgreSQL (relational + JSONB) via pgx + sqlc for persistence

- Status: Accepted
- Date: 2026-06-20
- Supersedes: [0004](0004-mongodb-storage.md)

## Context

Aurify persists users (with their DSP connections) and the covers they generate.
We originally chose MongoDB ([ADR 0004](0004-mongodb-storage.md)) for the
flexible document model. In practice the domain is overwhelmingly **relational**:
`User` is a clean aggregate with a one-to-many set of DSP connections, and
`Cover` is mostly scalar columns plus a foreign key to its owner. The only
genuinely document-shaped data is `Cover.Analysis` (a nested, still-evolving
`PlaylistAnalysis`).

We are early in development with **no production data**, so this is the cheapest
moment to switch to a store whose shape matches the domain.

## Decision

Use **PostgreSQL 17** with **mostly relational tables plus a single JSONB column**
for the evolving analysis payload. Access is **type-safe SQL generated by
[sqlc](https://sqlc.dev)** over the **`jackc/pgx/v5`** driver (`pgxpool`).

Schema (one migration today, see
`backend/internal/storage/postgres/migrations/`):

- `users` — `id` PK, unique `email`.
- `dsp_connections` — FK to `users(id) ON DELETE CASCADE`,
  `PRIMARY KEY (user_id, platform)`. A user + its connections are one aggregate,
  so writes run in a single transaction.
- `covers` — relational columns + `analysis JSONB`; index
  `(user_id, created_at DESC)` backs the paginated list query.

Supporting choices:

- **Migrations**: versioned SQL via **goose**, embedded with `embed.FS` and
  applied on startup in `postgres.Connect`. This also closes ADR 0004's
  "indexes not created in code" gap.
- **Codegen**: `sqlc generate` (config in `backend/sqlc.yaml`) produces the
  `internal/storage/postgres/db` package. It is checked in and regenerated when
  a migration or `query/*.sql` changes — the same checked-in-codegen pattern as
  `cmd/openapi` (see [ADR 0008](0008-openapi-contract.md)).
- **Domain decoupling**: `bson` tags are removed from the domain. Column mapping
  lives in SQL; the JSONB payload types (`PlaylistAnalysis` and friends) carry
  `json` tags to pin their encoding. This resolves the coupling smell ADR 0004
  flagged.
- IDs are generated application-side as UUID strings (`google/uuid`), replacing
  Mongo's hex object IDs.

## Consequences

- Real integrity: foreign keys and `UNIQUE` constraints the document model
  could not enforce; covers-by-user and future reporting are native SQL.
- `Cover.Analysis` stays schema-flexible as JSONB (no migration to add an audio
  feature) while everything else gains a typed schema.
- sqlc checks every query against the schema at codegen time — stronger
  guarantees than the previous untyped BSON, at the cost of a generate step in
  the backend workflow.
- The adapter is larger than Mongo's (~184 lines): explicit columns, row→domain
  mapping, a transaction for the user aggregate, and `pgtype.Timestamptz`
  conversions. The application/command/query layers are unchanged — all storage
  stays behind `ports.UserRepository` / `ports.CoverRepository`.

## Out of scope (future work)

- Token encryption at rest for `dsp_connections` (still flagged by
  [ADR 0005](0005-dsp-provider-abstraction.md)).
- Async cover generation / job queue (the handler remains synchronous).
- Data migration from MongoDB — unnecessary, there is no production data.
