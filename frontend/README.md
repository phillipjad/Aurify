# Aurify — Frontend (PWA)

React 19 PWA built with the [Vite+](https://viteplus.dev/) toolchain. Routing by
[TanStack Router](https://tanstack.com/router), async state by
[TanStack Query](https://tanstack.com/query), styling by
[Tailwind CSS v4](https://tailwindcss.com), components/icons via
[shadcn/ui](https://ui.shadcn.com) (+ `lucide-react`).

## Layout

```
src/
  main.tsx                 # app bootstrap: QueryClient + Router providers
  routeTree.gen.ts         # generated by the TanStack Router plugin (committed)
  routes/                  # file-based routes (__root, index, playlists, covers)
  components/ui/           # shadcn/ui components
  features/                # feature modules (playlists, covers)
  lib/
    query-client.ts        # shared TanStack QueryClient
    api/
      client.ts            # fetch wrapper (cookie auth, CSRF, silent refresh)
      auth.ts              # session query + sign-in/up/reset mutations
      schema.ts            # GENERATED from the backend OpenAPI spec (vp run gen:api)
      types.ts             # wire types, derived from schema.ts (no hand shapes)
      queries.ts           # READ side  — useQuery hooks (CQRS queries)
      commands.ts          # WRITE side — useMutation hooks (CQRS commands)
```

The CQRS split is mirrored on the client: **reads** live in `lib/api/queries.ts`
(TanStack `queryOptions`/`useQuery`) and **writes** in `lib/api/commands.ts`
(`useMutation`), matching the backend's command/query handlers.

## Toolchain (Vite+)

**Vite+ is the only toolchain here.** Every task — dev, format, lint, type-check,
test, build — runs through the unified `vp` CLI; there is no separate
`pnpm`/`vite`/`eslint`/`prettier` path. `vp check` formats with **Oxfmt**, lints
with **Oxlint**, and type-checks with **tsgolint** (replacing ESLint/Prettier/tsc).

Install the CLI once, globally:

```bash
curl -fsSL https://vite.plus | bash    # macOS/Linux  (Windows: irm https://vite.plus/ps1 | iex)
```

Then, from this directory:

```bash
vp install        # install dependencies (pnpm under the hood)
vp dev            # dev server on http://localhost:5173 (proxies /api -> :18080)
vp check          # format + lint + type-check (Oxfmt + Oxlint + tsgolint)
vp check --fix    # auto-fix formatting + lint
vp test           # run the Vitest suite (jsdom + Testing Library)
vp build          # production build (Rolldown)
```

Anything not covered by a built-in command runs through the task runner —
e.g. `vp run gen:api` regenerates the API types.

## Testing

Component and routing tests run on [Vitest](https://vitest.dev) (executed via
`vp test`) with Testing Library + jsdom. Tests live beside what they cover as
`*.test.ts(x)`, with shared setup in `src/test/setup.ts`. Coverage focuses on
behavior — DSP platform switching, theme toggling, query loading/empty/error
states — and real navigation through the generated route tree.

## Notes / TODO

- **Auth is cookie-based.** `lib/api/client.ts` sends credentials on every
  request, echoes the CSRF cookie in `X-CSRF-Token` on mutations, and silently
  refreshes once on a 401 before giving up. No token is ever read or stored by
  script — the access and refresh cookies are HttpOnly. Guarded routes go
  through `requireSession` in `lib/auth-guard.ts`, which is a UX redirect and
  not a security boundary; the API authenticates every request itself.
- Only the `button` shadcn component is included; add more with
  `vp dlx shadcn@latest add <component>`.
- Add the PWA icons listed in `public/icons/README.md`.

## API types (generated)

`lib/api/types.ts` derives its shapes from `lib/api/schema.ts`, which is
generated from the backend's OpenAPI spec — don't hand-edit DTO shapes. After a
backend contract change (`cd ../backend && go generate ./...`), run:

```bash
vp run gen:api      # ../backend/api/openapi.yaml -> src/lib/api/schema.ts
```

Everything in `types.ts` is derived from the spec, including the `Platform` and
`CoverStatus` string unions (the backend tags those DTO fields with
`enum:"..."`, and `binding:"required"` makes always-present fields non-optional).
See [ADR 0008](../docs/adr/0008-openapi-contract.md).
